Système d'Information "Ludothèque"

Python / Django MariaDB / SQLite3 Linux Debian 13 Git / SSH
Interface d'administration (Dashboard) du SI Ludothèque.

Le Concept : Nous avons construit de A à Z le "cerveau" numérique d'une entreprise de location de jeux de société. Ce n'est pas juste un "site vitrine", c'est une véritable application web dynamique qui permet d'interagir avec une base de données complexe. L'objectif était de livrer une infrastructure robuste, sécurisée, et déployée selon les standards professionnels.

1. L'Architecture Logicielle (Django MVT)

Pour construire ce projet de façon modulaire et maintenable, nous avons utilisé l'architecture Modèle-Vue-Template du framework Python Django.

  • Le Modèle (L'Architecte) : Le plan de notre base de données. Il dicte comment ranger l'information de manière stricte.
  • La Vue (Le Cerveau) : La logique mathématique. Elle vérifie si les formulaires sont valides et orchestre les requêtes.
  • Le Template (La Décoration) : L'interface visuelle isolée du code technique.
Arborescence modulaire des templates pour la création d'interfaces CRUD (Create, Read, Update, Delete).

2. L'Architecture Hybride (Bases de Données)

Nous avons résolu un problème majeur d'ingénierie logicielle : la dérive de configuration entre l'environnement de code et le serveur web. Le système s'adapte automatiquement :

  • En Développement (Sur nos PC) : Le code utilise SQLite3. Une base légère stockée dans un fichier local pour itérer rapidement.
  • En Production (Sur le serveur) : Le site détecte son environnement et bascule instantanément sur un serveur MariaDB capable d'encaisser la charge.
Initialisation et sécurisation du moteur MariaDB en ligne de commande.

3. Déploiement : La Chaîne Logistique (CI/CD)

Mettre un site sur internet ne se fait pas à la main. Nous avons mis en place un pipeline logiciel complet :

Configuration de l'OS serveur (Debian 13).
Travail collaboratif et versionnement sur GitHub.

Depuis nos terminaux, nous perçons un tunnel sécurisé (SSH) pour prendre le contrôle du serveur distant. La synchronisation se fait en rapatriant le code source depuis le dépôt GitHub directement sur l'infrastructure de production.

Rapatriement et synchronisation du code sur le serveur distant.
Traçabilité complète des versions (Git Log).

4. La Forteresse : Sécurité Intégrée

Un SI gérant des données est une cible permanente. Nous avons verrouillé les accès critiques :

  • Neutralisation des Injections SQL : L'utilisation de l'ORM de Django agit comme un filtre intraitable, transformant les requêtes malveillantes en texte inoffensif.
  • Jetons CSRF : Pour éviter la falsification de requêtes inter-sites, le système exige un ticket cryptographique à usage unique pour chaque formulaire soumis.
  • Isolation des Secrets (.env) : Les identifiants MariaDB et les clés de chiffrement de Django ne sont jamais versionnés dans le code. Ils résident dans un fichier caché directement sur le serveur de production.
